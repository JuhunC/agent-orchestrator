# Where things are (src/)
- `triggers.ts`: webhooks → intents (mentions, assignment, account aliases), sender permission, own-echo filter, redelivery dedupe, blocked senders, `accept()` creates tasks. `blocked-users.ts`: Settings → Blocked users (tables `blocked_users`, `blocked_replies` in db.ts; routes in `server/blocked-users-api.ts`; UI `web/src/components/BlockedUsers.tsx`): a blocked sender's intents get one reply per thread and agent (`answerBlocked`), nothing reaches running agents.
- `runner/run-task.ts`: one task end to end (workspace, prompts, session run, model retries, fallback model, usage limits, end of task: card moves, sub-issues, issue state, related starts, result comment). `scheduler.ts`: the queue: `startOrder` (`queue-order.ts`: `rank`, task `priority` from labels via `priorityFromLabels`, turns between requesters from `lastStarts`, `rankReason`), replicas, board `max_running`, `MAX_RUNNING_PER_REPO`, spend and usage limits, one writer per thread (`workKeys`, `noteWriterAhead`), host pressure (`hostHold`). `executor.ts`: where tasks run (`Executor`; `LocalExecutor` is this process): the scheduler calls `executor.run`, never `executeTask`, and asks `executor.pressure()` (`pressureOf`: `HOST_MIN_FREE_MEMORY_MB`, `HOST_MAX_LOAD`; one task always runs). `waits.ts`: tasks their agent paused with the `wait_for` tool (`task.waitFor`, `waits`, `waitReason: "wake"`; `checkWaits`, `wakeTask`). `inbox.ts`: GitHub activity reaching running agents (kept in table `inbox_notes`, so it survives a restart; `settleInbox` when a task ends). `progress.ts`: progress/result comments; live activity (the progress comment) only when `liveActivityFor(profile)`: `github.live_activity`, else the `live_activity` setting, else `LIVE_ACTIVITY` (off). `spend.ts`, `incidents.ts` (alerts, `/metrics`), `outcomes.ts`, `usage-report.ts`, `limits.ts`/`limit-store.ts`.
- `runtime/`: `mirrors.ts` (one shared bare copy per repository; checkouts borrow its objects), `github-tools.ts` (the agent's `github` MCP tools; write tools dry-run guarded), `session.ts` + `manager.ts` (Claude Code sessions: live, resume, model-proxy grants), `options.ts` (SDK options, agent env, fallback models), `workspace.ts` (checkouts), `isolation.ts` (agent OS user), `model-proxy.ts`, `related-agents.ts`, `sub-issues.ts`, `evidence.ts` (board move checks), `cleanup.ts`, `backup.ts`, `usage.ts`.
- How a task ends, in `run-task.ts`: a timeout, hang (`TASK_STALL_MINUTES`) or error is retried in the same session (`TASK_FAILURE_RETRIES`); the agent's `report_outcome` tool sets `task.outcome`/`outcomeNote` (`partial`, `blocked`, `gave_up`; incident `task_blocked`); then related starts and routes run (`runtime/related-agents.ts`: `runRoute`), only after success. After a merge, `checkConflictsInto` (outcomes.ts) checks agents' open pull requests (`openAgentPulls`).
- `agents/prompt.ts`: the prompts. A long thread is trimmed from its oldest comments; other agents' runs on the thread come from `othersOnThread` (db.ts); routing sections for agents that may pass work on.
- `routing.ts`: the triage agent (`TRIAGE_AGENT`/`TRIAGE_REPOS`, or Settings → Routing: `routing()`, `setRouting`, `triageAgentFor`, `mayRoute`, `routableAgents`). `triggers.ts` gives a new issue that names no agent to it (trigger kind `triage`); its `route_to_agent` tool (github-tools.ts; also for agents with `github.route`) passes the thread on. UI `web/src/components/Routing.tsx`.
- `github/`: `app.ts` (App, installation tokens, bot identity), `accounts.ts` (agents' GitHub accounts, own-write record), `threads.ts` (fetch thread, comments, `signed()` marker), `relations.ts`, `projects.ts`, `labels.ts`, `wiki.ts`.
- `boards/`: `loader.ts`, `rules.ts` (board file parsing), `engine.ts` (card moves, column agents, loop guards).
- `schedules/`: `when.ts` (cron/@daily/"every 6h" parsing, next run in a time zone, describe), `runner.ts` (add/change/remove, due runs every 30 s, agent.md sync, tracking issue, skip/pause/finish rules, prompt info), `tools.ts` (the agent's create/list/update/delete_schedule). Routes in `server/schedules-api.ts`; UI `web/src/components/Schedules.tsx`. Tasks carry `scheduleId`, trigger `schedule`.
- Base branches (where PRs go): `github/branches.ts` (pure: `parseBaseBranch` for board/agent.md values, string or owner/name map, `branchNameProblem`, `pickBase`); `runtime/base-branch.ts` (`chooseBase`/`baseForTask`: task.requestedBase (run/schedule/retry) > board > agent > Settings repo setting > default; `checkBranchExists`). `Workspace.targetBranch`/`targetFrom` = where non-sub-issue work goes; use it, not `thread.defaultBranch`, for "the main line". Routes `server/base-branch-api.ts`, UI `components/BaseBranches.tsx`. Merged agent PRs into a non-default base close their issue (`closeIssuesAfterMerge` in outcomes.ts).
- `profiles/`: `loader.ts` (agent.md, `GITHUB_DEFAULTS`), `reference.ts` (options reference), `types.ts`, `store.ts`, `version.ts` (profile fingerprint per task).
- `server/`: `api.ts` (every /api route), `auth.ts`, `roles.ts` (viewer/operator, audit log), `http.ts`, `secrets.ts` (`seal`/`unseal`).
- `db.ts`: schema (`CREATE … IF NOT EXISTS`, `addColumn` migrations) and all queries. `config.ts`: every env var.
- `web/src`: `api.ts` (shared types and hooks: `useApi`, `useStream`), `pages/`, `components/`. Built with Astryx (`@astryxdesign/core`, Neutral theme, set up in `main.tsx`); icons from `lucide-react`. `components/ui.tsx` holds the app's building blocks on top of it: `Panel` (titled card), `DataTable` (compact table sized to content; use Astryx `TableHeader`/`TableRow`/`TableCell` inside, `className="ao-clickable"` + `onClick` for row links), `Notice` (Banner), `KV` (label/value list), `Dialog` (with a footer of buttons), `StatTile`/`StatGrid`, `Columns` (two panels side by side), `Tag`/`Chips` (Tokens), `StatusPill`/`Pill` (Badges), `Meta` (secondary text), `ErrorText`, `A` (in-app or external link), `LinkButton`, `SuggestInput` (text field with a datalist), `Lines`. `styles.css` only covers what Astryx has no component for (task log, board map, usage chart, editor, run dots), using Astryx tokens (`--color-*`, `--spacing-*`). Astryx component docs: `npx @astryxdesign/cli component <Name>` (props: `--dense`). Use `<Code size="inherit">` inline; Astryx needs 2024+ browsers (build target in `web/vite.config.ts`).

# Adding something: also update
- **Env var** (`config.ts`): README configuration table and `.env.example`.
- **agent.md `github.*` key**: `profiles/types.ts`, `loader.ts` (`GITHUB_DEFAULTS`: `test/unit.test.ts` requires each key documented in `reference.ts` with the same default; `null` defaults are skipped), `web/src/api.ts`, an AgentDetail chip if people should see it.
- **Other agent.md key**: `loader.ts`, `types.ts`, `reference.ts`, `web/src/api.ts`.
- **Board file key**: `boards/rules.ts` parser (unit test), `boards/loader.ts`, `reference.ts`, `profiles/boards/product.yaml.example`.
- **Task field**: `types.ts`, `db.ts` (`addColumn`, `toTask`, `NewTask`, `createTask`, `TASK_COLUMNS` if it changes), `web/src/api.ts`.
- **Queries about real work** must skip dry runs: `AND dry_run = 0`.
- **Agent tool that writes to GitHub**: add it to `WRITE_TOOLS` in `github-tools.ts` (dry runs); bodies go through `signed()`/`clampBody` so the orchestrator recognises its own webhooks.
- **Admin write route**: if operators may use it, add it to `OPERATOR_WRITES` in `server/roles.ts`.
- **A problem worth alerting on**: `recordIncident(kind, severity, message)` and the kind in `incidents.ts`.
- **A new limit**: add a row to the `/api/guards` list in `server/api.ts` (Settings → Loop guards).
- **Background job**: hourly timers live in `startWorkspaceCleanup`, `startOutcomeChecks` (pull requests, branch cleanup), `startAccountChecks`, `startBackups`/`startRetention`, `startBoards` (polling, archiving), `startSchedules` (every 30 s); start them in `index.ts`, `.unref()` the timers.
- **Folders the agent user must read or write** (isolation): add to `sharedRoots()` in `isolation.ts`; git run there must go through `git()` (it keeps files group-readable).
- README: the matching section; keep sentences short and plain.
